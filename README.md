# WB Pulse

Бот для продавца Wildberries: новые заказы и отмены приходят в Telegram, остатки по складам выгружаются в Google Таблицу, а когда товар заканчивается, приходит предупреждение.

```
🛒 Новый заказ
Худи · Тестовый бренд
Артикул HD-OVR-BLK, размер L
Цена для покупателя: 2 785 ₽
Склад: Коледино · Москва

⚠️ Заканчивается товар (порог 5 шт.)
• HD-OVR-BLK [L]: 3 шт. (Коледино: 2, Электросталь: 1)
• TSH-BASIC-WHT [M]: 3 шт. (Казань: 3)
```

## Что умеет

- присылает каждый новый заказ один раз, даже если WB отдал его повторно или бот перезапустили;
- сообщает об отменах;
- суммирует остатки по всем складам и предупреждает, когда позиция падает ниже порога. Предупреждает один раз, а после пополнения снова следит;
- при первом подключении не засыпает чат заказами за сутки, а шлёт одну сводку;
- пишет заказы и остатки в Google Таблицу (по желанию);
- работает в демо-режиме на тестовых данных, без кабинета продавца.

## Быстрый старт

```bash
pip install -r requirements.txt
python -m wb_pulse.main --demo --once     # демо: сообщения печатаются в консоль
```

На реальном кабинете:

1. Токен WB: кабинет продавца, Настройки, Доступ к API, категория «Статистика», только чтение.
2. Telegram: создать бота у @BotFather, узнать свой chat_id.
3. Скопировать `.env.example` в `.env` и заполнить.
4. Запуск: `python -m wb_pulse.main` (постоянно) или `--once` по расписанию через cron.

## Как устроено

```
wb_pulse/
  wb_client.py  запросы к Statistics API WB и демо-клиент с теми же методами
  logic.py      вся логика: новые заказы, отмены, сводка остатков, тексты сообщений
  state.py      память между запусками: какие заказы уже отправлены
  notify.py     отправка в Telegram (без токена печатает в консоль)
  sheets.py     выгрузка в Google Таблицу через сервисный аккаунт
  main.py       цикл: заказы раз в N минут, остатки раз в 30 минут
tests/          тесты логики без сети
```

Решения, которые стоит знать:

- **Дубли.** WB возвращает заказ заново, когда он меняется. Ключ заказа `srid`, бот хранит уже отправленные в `state.json` и сверяет с ними.
- **Пропуски.** Заказы запрашиваются с запасом в 10 минут назад, потому что WB иногда добавляет их с задержкой. Дубли от запаса отсекает пункт выше.
- **Лимиты WB.** Методы статистики принимают 1 запрос в минуту. Заказы и остатки разведены по времени, при ответе 429 бот ждёт и пробует один раз.
- **Остатки.** WB обновляет их раз в 30 минут, чаще спрашивать нет смысла.
- **Надёжность.** `state.json` пишется через временный файл, чтобы при сбое не потерять историю. Логика отделена от сети, поэтому покрыта тестами.
